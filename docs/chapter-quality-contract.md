# DeepSeek Harness 章节质量合同

本合同复用 `opencode-feynman-module` 与 `opencode-feynman-module-teacher` 的教学方法，源码权威切换为 DeepSeek Harness 固定提交 `47f943859bef60e4160492346772ded9b24f765a`。

## 1. 学习者与目标

- 学习者有 Java 后端经验，正在学习 TypeScript、Cordis 与 Agent 架构。
- 每章必须让学习者能够先画出系统位置，再沿真实源码追踪一次输入，最后把方法迁移到自己的 Agent。
- 章节不是 API 清单、README 翻译或文件目录。每章只回答一个中央问题，但要把这个问题讲完整。

## 2. 章节骨架

每章保留以下开头，并按主题调整后续标题：

1. `0. 本章学习目标`：3–6 个可验证成果。
2. `1. 一句话讲明白`：可复述的一句话和一个中央问题。
3. 为什么现在需要理解它：先处理学习者的困惑。
4. 位置图与边界：画出本模块、上游、下游和不负责的部分。
5. 最小机制：用短伪代码、类型形状或状态机剥离产品细节。
6. 读源码前的必要概念：只解释会阻碍后续阅读的语法或类型。
7. 一次真实源码旅程：按执行顺序追踪一条具体请求、事件或工具调用。
8. 深挖决定性分支：类型、状态变化、停止条件、失败路径和扩展点。
9. DeepSeek Harness 的选择：比较替代方案与源码展示的取舍。
10. 可以带走的方法：2–3 个可迁移工程方法，每个附验证问题。
11. 费曼复述、自测与练习：从只读定位到小型实现。
12. 小结与下一章钩子：提出一个真实未解问题。

结构服从主题，不强迫机械使用完全相同的标题，但概念顺序不能倒置。

### 叙事节奏

参考 Pi Agent Book 的可迁移方法，但不复制其文字：

- 用一个具体场景贯穿整章，让同一条请求、事件或状态在每一层继续向前走。
- 先说“最直觉的实现”，再用生产约束证明它为什么不够，最后进入 Harness 的实际选择。
- 抽象结构要用具体对象逐步长出来：展示字段、父子关系、状态前后值或事件序列，而不只给最终总图。
- 每段代码后解释输入、输出、状态变化与设计原因；不能用代码块代替讲解。
- 主动纠正至少一个常见误读，核对真正的条件、信号来源或调用顺序。
- 图和表之后写出读图结论，告诉学习者应该从视觉材料中得到什么。
- 开头承接上一章暂时保留的黑盒，结尾打开下一章要解决的问题。

## 3. 证据纪律

- 所有源码链接必须指向固定提交，不得链接 `master`。
- 每个关键行为至少有一个权威文件与有效行锚点；链接前用本地源码重新核对。
- 明确写出“源码事实”“设计解读”或“教学推演”，不能把推断伪装成运行记录。
- 一章至少使用 5 个相关源码文件，避免只围绕一个大文件做摘要。
- 代码片段只保留证明机制的行，并注明是节选或教学伪代码。
- Java 类比只能作为桥梁；每次类比都要说明哪里不再对应。

## 4. 内容下限

这是防止再次退化成提纲的下限，不是鼓励灌水：

- 正文不少于 220 行、7000 个字符。
- 至少 10 个二级或三级教学段落。
- 至少 1 张位置图或时序图、1 个最小机制代码块、1 张真实差异表。
- 至少追踪 1 条端到端源码路径，并明确每一步输入、输出与状态变化。
- 至少讲清 2 个失败、停止或安全边界。
- 至少 5 个费曼自测问题和 3 级练习任务。

如果一个主题无法自然达到下限，先检查选题是否过大或证据是否尚未读够，不用重复句子填充。

## 5. 逐章验收问题

- 开头是在解释学习者的问题，还是在罗列仓库目录？
- 学习者能否在阅读函数前画出位置图？
- 最小机制与产品附加层是否清楚分开？
- 真实旅程是否按调用顺序，而不是按文件名顺序？
- 每个深挖段落是否回答“是什么、怎么实现、为什么这样设计”？
- 是否至少说明一个停止条件和一个失败恢复路径？
- 是否能从本章提炼出可用于其他 Agent 的方法？
- 下一章是否由当前章留下的真实问题自然引出？

## 6. 完成前验证

在站点目录运行：

```bash
pnpm run validate:sources
pnpm run check
pnpm run build
```

构建成功只证明页面可生成；仍需人工抽查固定提交、路径、行锚点、调用顺序和教学完整性。
